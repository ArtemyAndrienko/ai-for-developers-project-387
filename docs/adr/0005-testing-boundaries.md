# Границы тестирования: верхний достаточный шов

Решено (билет #7 карты wayfinder): каждое доменное правило тестируется на самой высокой границе, где оно полностью выражается; чистые функции → unit, поведение Store на SQLite → Store-шов, маршруты/методы → check-contract. HTTP e2e вводим только для свойств, ниже не возникающих: параллельная конкуренция запросов (контрактное «ровно одна Запись succeeds» из билета #5 карты) и корректность маршрутизации/JSON/кодов. Форма — `httptest.Server` поверх извлечённого `newMux(store)` и настоящая SQLite во временном каталоге, интеграция в `mise run test` и CI.

## Considered Options

- **Чёрный ящик на запущенном бинаре** — хрупкость портов/процесса, тестирует stdlib, а не логику.
- **Дублирование Store-матрикса поверх HTTP** — третья копия тех же правил.
- **Отказ от e2e** — гарантия конкуренции так и остаётся непроверенной поверх HTTP.

## Consequences

Рефакторинг `main.go` (`newMux`) — предпосылка e2e; обязательный набор сценариев перечислен в README «Тесты»; сборка оформлена билд-тикетом.

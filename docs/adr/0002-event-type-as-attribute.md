# «Тип события» — атрибут Встречи, не сущность

Продукт говорит «тип события» («слот длится столько, сколько выбранный тип события»), но единственный признак типа сегодня — длительность Интервала. Решили: не вводить сущность EventType и справочник типов в схеме или контракте — «тип события» есть атрибут Встречи `durationMin`. Канонический набор длительностей 15/30/45/60/90/120/150/180 минут закреплён в глоссарии как пресеты UI; сервер проверяет только диапазон.

## Considered Options

- **Именованный справочник типов** (Meeting → EventType): нужен именованным/recurring типам — их заказ нет; потянул бы миграцию, контракт и экран управления без выигрыша.
- **Редактируемый каталог в профиле Организатора**: спекулятивная общность до появления реальной потребности.

## Consequences

Список длительностей становится нормативным для UI-пресетов (в форме создания сейчас не хватает 150/180). Если появятся именованные типы или recurring — решение пересматривается новой картой, и этот ADR будет superseded.

# Часовой пояс: IANA-зона Организатора, wall-clock-якорь

Отложенный пункт бэклога решён (билет #4 карты wayfinder): часовой пояс — IANA-идентификатор (`Europe/Moscow`), хранимый в профиле Организатора (первое per-person свойство в базе); Рабочий день, календарные даты, 14-дневное окно и вердикт «уже прошло» вычисляются в нём. Сетка остаётся wall-clock (`plainTime`) — не UTC-инстансами; для детерминизма бинарь встраивает базу часовых поясов (`import _ "time/tzdata"`).

## Considered Options

- **Таймзона на паре (организатор, дата) или на Встрече**: допускает несколько «сегодня» внутри одного окна — неразрешимо; отказ.
- **Фиксированное смещение (+03:00)**: врёт при DST и молча лжёт при переезде; отказ.
- **UTC-инстансы как канон сетки**: другая доменная модель («календарь инстансов»), ломает определение Рабочего дня и большую часть сеточной логики. Переход к ней остаётся возможным из текущей модели (IANA известен), обратный — дороже.

## Consequences

Посетитель из другого региона видит часы Организатора, пока карта не решит отображение (отдельный билет). Сервер в UTC (CI-раннеры) перестаёт влиять на «сегодня» — время больше не берётся из локации процесса.
